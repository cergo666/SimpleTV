# Flutter desktop: Windows и Linux

## Тема и шрифты

- Токены — `AppColors`, `AppType`, `AppRadius`, `AppSpace` в `desktop/lib/ui/theme/theme.dart`.
- Шрифт выбирается по платформе: `Segoe UI` на Windows, `Ubuntu`/`Cantarell` на Linux, с fallback. Не задавай один шрифт, которого нет на Linux.
- Не хардкодь цвета и размеры в виджетах, если есть токен.

## Окно и адаптивность

- Минимальный размер окна — не меньше 960×600; проверяй 1280×720, 1600×900 и полноэкранный режим.
- Широкий режим (`wide`) включает боковые элементы и большие отступы; компактный — прячет второстепенное, но не главное действие.
- Длинные названия каналов, источников и передач не должны ломать строку: `maxLines` + `TextOverflow.ellipsis`.
- Списки — `ListView.builder`/`GridView.builder` с ключами; не собирай длинные списки в `Column`.

## Управление

- Все действия доступны мышью и с клавиатуры. Основные: Enter/Space — выбрать, Esc — закрыть оверлей, стрелки — навигация по списку, пробел — пауза.
- Hover и focus — разные состояния, но оба видимы. Не прячь кнопку до наведения.
- Tooltip обязателен для иконок без подписи.
- Курсор над интерактивным элементом — `SystemMouseCursors.click`.

## Оверлеи и навигация

- Оверлей (плейлист, настройки, статистика) закрывается Esc и кликом вне, если это не разрушительное действие.
- Не открывай модальное окно для задачи, которую можно решить inline.
- Фокус после закрытия возвращается на элемент, который открыл оверлей.
- У модальных окон есть заголовок, кнопка закрытия и понятное основное действие.

## Состояния и обратная связь

- Загрузка — индикатор + текст, что именно грузится.
- Ошибка — причина и кнопка повтора; не только красная иконка.
- Пустое состояние — объяснение и действие («Загрузить плейлист»).
- Долгие операции не блокируют окно; повторный клик не запускает вторую операцию.

## Визуальная проверка

- `cd desktop && flutter analyze && flutter test`
- Сборка: `flutter build windows --release` (на Windows) или `flutter build linux --release` (на Linux).
- Если окно не открывалось, не утверждай, что вёрстка проверена. В отчёте разделяй анализ кода и визуальную проверку.
